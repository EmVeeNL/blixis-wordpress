# Layout configuration contract version 1

**Status: implemented (task [03-07](../../roadmap/phases/03-child-theme-setup-wizard/07-theme-layouts-and-style-presets.md) Part A): the schema, the PHP and TypeScript validators, the fixtures, and the stored option. Nothing renders the configuration yet and there is no interface; both arrive in the next step of 03-07 (see [layout configuration](../../development/LAYOUT.md)).**

`BlixisLayoutConfig` holds the chosen layout and the header and footer settings of a child theme. It is a separate contract from the [token contract](../tokens/README.md), with the same guarantees: closed names, a normalizing validator that returns sorted `{code, path}` errors, PHP as the authority and TypeScript for the browser, shared fixtures that both validators must pass, a stored row with a revision and a hash, compare-and-swap saves, and rollback. It is not part of `BlixisThemeConfig`, because it changes at other moments and for other reasons (a sticky header is not a design token).

## Files

| Path | Purpose |
|---|---|
| [`v1/layout-map.json`](v1/layout-map.json) | Closed enums, grammars, limits, error codes, placeholders, and the defaults. Both validators load it. Generated by `packages/tokens/scripts/layout-contract.ts` |
| [`v1/blixis-layout-config.schema.json`](v1/blixis-layout-config.schema.json) | JSON Schema for the normalized form (generated). Patterns use ECMA-262 semantics |
| [`v1/valid/`](v1/valid/) | Configs that must pass |
| [`v1/invalid/`](v1/invalid/) with [`expected.json`](v1/invalid/expected.json) | Parseable configs that must fail with exactly the listed codes and paths |
| [`v1/raw-cases.json`](v1/raw-cases.json) | Base64 bytes that cannot be a parseable `.json` file, or that test number and escape spellings: BOM, invalid UTF-8, lone surrogates, duplicate keys, depth, size, `1e400` |
| [`v1/golden/canonical-and-hash.json`](v1/golden/canonical-and-hash.json) | For every valid fixture, the canonical JSON of the normalized config and its hash, produced by the PHP code |

The map is shipped twice, in `packages/tokens/src/layout-map.json` and `plugins/blixis-blocks/inc/layout/layout-map.json`; a test keeps the three copies byte-identical.

## Shape

```jsonc
{
  "schemaVersion": 1,
  "theme": { "slug": "acme-site" },
  "layout": "blank",                       // blank | business | portfolio | blog | landing
  "header": {
    "sticky": false,
    "usp": { "enabled": false, "items": [] },
    "logo": "start",                       // start | center
    "cta": { "enabled": false, "text": "", "url": "" },
    "search": false,
    "mobileMenu": "mobile"                 // mobile | always
  },
  "footer": {
    "stickToBottom": true,
    "columns": 1,                          // 1 to 4: site info, menu, contact, social
    "contact": "",
    "social": [],                          // { "service": "facebook", "url": "https://..." }
    "copyright": { "enabled": true, "text": "© {year} {site}" },
    "backToTop": false
  }
}
```

Every key is required and every object is closed (`field.required`, `field.unknown`). Defaults belong to the wizard: `defaults()` (PHP) and `layoutDefaults()` (TypeScript) return the configuration above, which is the one in [`v1/valid/default.json`](v1/valid/default.json). The validator never completes a missing key.

| Field | Rule |
|---|---|
| `schemaVersion` | The number 1 (`1.0` is accepted as 1, as in the token contract). Another number is `schema.version_unsupported` |
| `theme.slug` | The token contract's slug rule (`^[a-z][a-z0-9-]{0,62}$`; a test keeps the two equal). There is no `theme.parent`: that is a token field, so it is `field.unknown` here |
| `layout` | One of the five names (`layout.invalid`) |
| `header.sticky`, `header.search`, `footer.stickToBottom`, `footer.backToTop`, every `enabled` | Booleans |
| `header.logo` | `start` or `center` (`header.logo.invalid`) |
| `header.mobileMenu` | `mobile` (the overlay menu only on small screens) or `always` (`header.mobile_menu.invalid`) |
| `header.usp.items` | 0 to 3 plain-text items of 1 to 60 characters, each a single line (`header.usp.too_many`). With `enabled` true there must be at least one (`header.usp.empty`); with `enabled` false the items are kept and still validated |
| `header.cta.text` | Plain text, single line, 1 to 30 characters when `enabled`, 0 to 30 when not |
| `header.cta.url` | `http://` or `https://` URL, or a site-relative path starting with one `/`. Required when `enabled` (`url.empty`); when not enabled it may be empty, but a value that is there must still be valid (`url.invalid`) |
| `footer.columns` | An integer from 1 to 4 (`footer.columns.invalid`; `2.0` counts as 2). The columns appear in a fixed order: site info, menu, contact, social. Column *n* shows the first *n* of them; the value of a column that is not shown stays stored |
| `footer.contact` | Plain text, 0 to 200 characters, line feeds allowed |
| `footer.social` | 0 to 6 objects `{service, url}` (`footer.social.too_many`). `service` is one of `facebook`, `instagram`, `linkedin`, `x`, `youtube`, `tiktok`, `mastodon`, `bluesky`, `github`, `other` (`footer.social.service_invalid`). `url` is an `https://` URL. A service may appear more than once (two `other` links) |
| `footer.copyright.text` | Plain text, single line, 1 to 120 characters when `enabled`, 0 to 120 when not. The only braces allowed are the placeholders `{year}` and `{site}`, in lower case (`text.placeholder_unknown`) |

## Plain text

Text is plain text. It is stored as entered, after a trim, and escaped when it is printed. The contract does not escape, because HTML entities in a stored value would be a second encoding. It refuses what could never be shown as plain text:

- **Trim.** Spaces (U+0020) and line feeds (U+000A) at both ends are removed. Nothing else is: not a no-break space, not a tab (a tab is refused), and not the Unicode whitespace that `String.prototype.trim` would remove, so both languages agree.
- **Length** counts Unicode code points after the trim, so an emoji counts once and a line feed in `contact` counts once.
- **Control characters** (`text.control_char`): every `Cc` character (U+0000 to U+001F, U+007F to U+009F), U+2028, U+2029, the bidirectional overrides and isolates U+202A to U+202E and U+2066 to U+2069, and U+FEFF. A line feed is allowed only in `footer.contact`. The joiners U+200C and U+200D and the direction marks U+200E and U+200F stay allowed, because Arabic and Persian need them.
- **Markup** (`text.markup`): `<` and `>`. An ampersand, quotes, and braces (outside the copyright) are allowed and are escaped on output.
- **Checks run in this order and report the first failure:** control character, markup, empty (`text.empty`), too long (`text.too_long`), unknown placeholder. Each value gets at most one error.

## URLs

URLs are validated here, not only on output, because a stored URL would otherwise reach the page unchecked. They are not trimmed: a space makes them invalid, so the wizard must trim what it sends. The grammar is ASCII only, so both validators agree without Unicode rules; a non-ASCII character must be percent-encoded and a non-ASCII host written in punycode.

- At most 2048 characters (`url.invalid`).
- **Absolute:** lower-case `http` or `https` (social links: `https` only), then a host of dot-separated labels of letters, digits, and inner hyphens (1 to 63 characters each, no empty label, no trailing dot), an optional port of one to five digits, and an optional path, query, and fragment. No user information (`https://good@evil`), no IP literal in brackets, no backslash. Host names may be upper case; the stored value is not changed.
- **Site-relative** (CTA only): `/` followed by anything except another `/` or a backslash. `//evil.test` is not relative. `#anchor` and `?query` alone are not accepted; write `/#anchor`.
- The path characters are the RFC 3986 unreserved and reserved characters and `%XX` escapes. `<`, `>`, quotes, a backtick, braces, `|`, `^`, a space, and any control character are refused. Port numbers are not range-checked.
- `javascript:`, `data:`, `mailto:`, `tel:`, `ftp:`, `file:` and every other scheme fail the grammar.

## Validation order and errors

Order: size (32 KiB), depth (8, measured on raw bytes), JSON parse, `config.not_object`, schema version, then fields. A missing, wrongly typed, or unsupported `schemaVersion` stops validation; otherwise all errors are returned, sorted by the UTF-8 bytes of `path`, then `code`. Paths are RFC 6901 pointers; the root is `""`. Array items are `…/items/0`, and `/10` sorts before `/2` because the sort is by bytes.

A conforming implementation must also, as for the token contract: decode so that `{}` and `[]` differ (PHP: object mode), make `$` strict (PCRE: the `D` modifier), treat `1.0` as the integer 1, reject lone surrogates and keys starting with NUL, and measure depth before parsing.

| Code | Where |
|---|---|
| `config.too_large`, `config.too_deep`, `config.invalid_json`, `config.not_object` | Root (`""`) |
| `schema.version_unsupported` | `/schemaVersion` |
| `field.required`, `field.unknown`, `field.wrong_type` | Any key |
| `theme.slug.invalid` | `/theme/slug` |
| `layout.invalid` | `/layout` |
| `header.logo.invalid`, `header.mobile_menu.invalid` | `/header/logo`, `/header/mobileMenu` |
| `header.usp.too_many`, `header.usp.empty` | `/header/usp/items` |
| `footer.columns.invalid` | `/footer/columns` |
| `footer.social.too_many` | `/footer/social` |
| `footer.social.service_invalid` | `/footer/social/N/service` |
| `text.control_char`, `text.markup`, `text.empty`, `text.too_long`, `text.placeholder_unknown` | The text value |
| `url.empty`, `url.invalid` | The URL value |

A test checks that every code in `layout-map.json` is produced by at least one fixture and that no fixture produces an unlisted code.

## Persistence

One autoloaded option, `blixis_layout_config`, holds JSON with `revision`, `hash`, `config`, and `previous`, written like the token row: one compare-and-swap `UPDATE` on the exact stored bytes (a hash of the bytes is compared, because `=` on the column ignores case). `store_write()` validates the incoming bytes and returns `blixis_layout_invalid` (400, with the errors), or `blixis_layout_conflict` (409) when the revision moved or another writer won the race. `store_read()` revalidates the stored config and checks the stored hash and returns null for a bad row; `previous_config()` offers the fallback. `store_rollback()` writes the previous config as a new revision, so a rollback can be undone. A save fires `blixis_layout_saved( $revision, $hash )`. Writing needs `edit_theme_options` (`can_manage()`); the store functions do not check it themselves, the routes and handlers that call them must. The row is not a registered setting and nothing public reads it.

The hash is the first 16 hexadecimal characters of the SHA-256 of the canonical JSON (keys sorted, no whitespace, slashes and Unicode unescaped), the same as the token hash.

## Versioning and migration

`schemaVersion` 1 is the only version. `migrate_config()` and `migrateLayoutConfig()` are pure functions that bring a config that already passed validation at its own version up to the current one, one version at a time; they are the identity today, and storage already reads and writes through the PHP one. A later version adds a step, keeps the older grammars in the map (`legacyVersions`, as the token map does), validates a stored older config under its own rules, and migrates it on read and on save. Adding an enum value (a new social service, a new layout) widens the contract: validators must ship together, and a stored value stays valid.

## Choices beyond the first proposal

These were refinements made while specifying; each has fixtures.

- `header.usp.empty`: a USP bar that is on needs an item, otherwise it would render an empty list.
- A CTA that is on needs text and a URL; a copyright line that is on needs text. Values kept while switched off are still validated, so no unchecked text or URL is ever stored.
- `bluesky` is a social service; the list is closed and extended by a contract change.
- `theme` holds only `slug`.
- Control characters, bidirectional overrides, and angle brackets are refused in text (see above).
- URLs are ASCII only, not trimmed, at most 2048 characters, and accept site-relative paths only for the CTA.
- The maximum size is 32 KiB (six 2048-character URLs and the texts fit with room to spare).

## Reproduce

The derived files come from two scripts in `packages/tokens`:

```bash
cd packages/tokens
node scripts/layout-contract.ts     # layout-map.json (contract and both shipped copies) and the schema
node scripts/layout-fixtures.ts     # valid and invalid fixtures, expected errors, raw cases, goldens from the PHP code
npx -y pnpm@12.18.0 run test
```

`layout-contract.ts --check` fails when a derived file is stale; the tests run it. Expected errors are written by hand in `layout-fixtures.ts`, not taken from either validator; the goldens come from PHP and must be reviewed, because a changed golden is a contract change.
